# FeedNote

FeedNote 是一个本地持久化、可追溯的个人记忆系统。它先可靠保存原始输入，再由 Memory Engine 调用用户授权的模型自动分类、命名和摘要；只有遇到无法忠实理解的歧义时才询问用户。

## 当前能力

- 快速输入和原始记录时间线；
- 独立“备忘录”区域：选中文字后选择“记”，原文立即本地保存并单向追加到独立飞书表格；
- SQLite 本地持久化与全文搜索；
- 记忆类型、来源和版本时间线；
- DeepSeek `deepseek-v4-flash` 自动分类、标题和摘要，默认关闭思考模式；
- 自动判断新建、更新已有记忆或建立关联，更新始终创建新版本；
- Embedding 不可用时自动回退 SQLite 全文检索；
- 指代不明或关键上下文缺失时进入待澄清区；
- 模型不可用时安全降级为普通记事本；
- 永久删除确认和 JSON 数据导出；
- 系统托盘与 `Alt + Shift + Space` 全局唤起；托盘左键打开主窗口，右键可选择“打开 FeedNote”或“退出 FeedNote”，桌面浮标右键提供相同菜单；
- 设置页可选择是否随 Windows 登录自动在后台启动，默认关闭，并以系统实际启动项状态为准；
- Windows 任意应用选中文字后在选区起点左上方显示投喂圆点，并自动限制在多显示器可见范围内；明确选择“喂”后才保存并调用模型；
- 对微信等未暴露 UI Automation 文本选区的软件，可把选中文字直接拖到屏幕右侧 FeedNote 图标，再选择“喂 / 记 / 藏”；该入口只接收拖放载荷中的纯文本；
- 选区弹窗提供“喂 / 记 / 藏”：“记”保存没有确定时间的想法且不调用 LLM；“藏”将秘密原文加密保存在独立保险箱，LLM 只接收脱敏周边文本来补充元数据；
- 独立“秘密备忘录”使用 Argon2id 派生的主密码解锁，支持显示、复制、编辑和永久删除；每次永久删除必须重新输入主密码，主密码没有找回通道；
- AI 从同一文本控件的有限周边内容提取完整时间，缺时间时直接询问；
- 用户授权 AI 自行选择时间时，会参考其他未完成计划并保持至少 60 分钟的开始间隔；用户明确指定的时刻不做自动改动；
- 透明桌面计划卡片与屏幕右侧折叠 logo，面板透明度可调并在重启后保留；
- 计划卡片自动提取时间、标题、事项类型、链接和注意事项，链接交给系统浏览器打开；
- 主窗口提供独立“桌面计划”页面，可查看进行中或全部计划，编辑标题、时间、内容、详情、链接和注意事项，并标记完成或重新打开；编辑沿用原计划 ID 和飞书任务映射；
- 计划标签：投喂面试相关内容时自动标记“面试”，主窗口和桌面计划坞默认显示全部标签，也可只看面试计划；
- 可选 ntfy / Webhook 手机提醒，支持准时或提前 5/15/30/60 分钟推送；
- 可选飞书电子表格同步，一条计划对应一行，并双向同步已有计划的完成或重新打开状态；
- 可选飞书待办提醒，每条有明确时间的计划对应一个个人飞书任务，双向同步已有任务的标题、开始时间和完成状态，并固定在开始前 3 小时提醒；
- 求职投递记录表改为用户自行维护；FeedNote 不读取或写入其中的表格单元格；
- 可选飞书秘密表同步，将已解锁的本地秘密单向写入独立表格，便于手机查看；该表中的秘密值是明文；
- “记”会把用户明确选择的文字单向追加到独立“FeedNote 备忘录”表格，失败时保留本地记录并后台重试；
- 投递路由已停用：职位信息只保存在记忆库，明确的未来事项仍可创建桌面计划；
- 浏览器预览模式，便于不启动桌面壳时检查界面。

完整边界和架构见 [TECHNICAL_DESIGN.md](TECHNICAL_DESIGN.md)。

## 磁盘位置

为了避免占用 C 盘，本项目将大型内容固定在项目目录：

```text
.tooling/rustup      Rust 工具链
.tooling/cargo       Cargo 缓存
.tooling/npm-cache   npm 缓存
.tooling/target      Rust 构建产物
node_modules         前端依赖
data/feednote.db     应用数据
data/secrets.env     本机密钥，不进入数据库或导出
```

这些路径均已加入 `.gitignore`。请通过 `scripts` 中的脚本运行项目，以保证环境变量生效。

## 运行

已经构建好的版本可以直接双击项目根目录的 `FeedNote.exe`。它不需要启动开发服务器，数据会写入同目录的 `data` 文件夹。

开发时只预览界面：

```powershell
.\scripts\preview.ps1
```

浏览器访问 `http://127.0.0.1:1420`。

运行桌面应用：

```powershell
.\scripts\dev.ps1
```

执行全部测试：

```powershell
.\scripts\test.ps1
```

构建桌面可执行文件：

```powershell
.\scripts\build.ps1
```

## 模型配置

基础记录、搜索、导出不依赖模型。当前默认使用 DeepSeek Anthropic 兼容接口，密钥只从下面的文件读取：

```text
data\secrets.env
```

最小配置：

```env
DEEPSEEK_API_KEY=
```

LLM 地址和模型使用应用内默认值 `https://api.deepseek.com/anthropic` 与 `deepseek-v4-flash`。它使用非思考模式处理分类、路由和时间提取；若要单独指定更轻量的路由模型，可添加 `DEEPSEEK_SMALL_FAST_MODEL=`。可运行 `./scripts/configure-deepseek.ps1` 安全写入 Key；命令执行后，在隐藏输入提示中粘贴 DeepSeek 控制台生成的真实 API Key，而不是再次输入脚本命令。脚本不会回显密钥，并拒绝路径、命令和格式异常的值。Embedding 仍独立使用智谱 `embedding-3`、512 维且只读取 `EMBEDDING_API_KEY`，绝不向智谱发送 DeepSeek Key；没有可用 Embedding 凭证或额度时自动回退本地 FTS5。

未来本地小模型通过 Provider 接口接入；原始数据结构和 Memory Engine 不与 DeepSeek 绑定。

## 手机提醒配置

手机提醒默认关闭。首版推荐使用 ntfy：在手机安装 ntfy，订阅一个足够长且不可猜测的私有主题，然后在 `data\secrets.env` 添加：

```env
MOBILE_PUSH_ENDPOINT=https://ntfy.sh/feednote-替换为足够长的随机主题
MOBILE_PUSH_TOKEN=
```

受保护主题或自托管 ntfy 可在 `MOBILE_PUSH_TOKEN` 填写访问令牌。也可以在应用设置中选择 `webhook`，此时同一地址会收到只包含 `event`、`title`、`body`、`linkUrl` 和 `scheduledAt` 的 JSON。配置完成后，在“设置 -> 手机提醒”中开启并发送测试提醒。

## 飞书计划表配置

飞书同步默认关闭，使用企业自建应用的应用身份。应用需要发布，并开通以下最小权限：

```text
sheets:spreadsheet:create
sheets:spreadsheet:read
sheets:spreadsheet:write_only
task:task:write
sheets:spreadsheet.meta:read
```

在 `data\secrets.env` 添加：

```env
FEISHU_APP_ID=
FEISHU_APP_SECRET=
```

也可以运行 `scripts\configure-feishu.ps1`，App Secret 会使用隐藏输入并写入密钥文件，不显示在终端。

然后打开“设置 -> 飞书计划表”，开启同步并点击“初始化并同步”。FeedNote 会创建“FeedNote 计划”电子表格，写入现有计划，并在后续新增、补充时间或标记完成时更新对应行。表格中已有计划的“状态”改为“已完成”或“已安排”后，FeedNote 会在约 30 秒内回读；其他列仍以本地数据为准。同步失败不会回滚本地记录，后台会保留待同步状态并重试。

打开“设置 -> 飞书待办提醒”后，FeedNote 会为所有有明确时间且未完成的计划创建飞书任务。任务开始时间和截止时间均取计划时间；提醒默认提前 180 分钟，但用户在投喂文本中明确要求准时、到点或其他提前量时按单条计划覆盖，也可在桌面计划编辑器中修改。计划改期、改名、提醒、完成或重新打开会更新同一个任务。在飞书任务中修改标题、精确开始时间、完成或重新打开，也会在约 30 秒内回写 FeedNote；FeedNote 采用飞书开始时间，只有开始时间缺失时才回退到截止时间。全天任务、任务描述和未映射的新任务不会覆盖或创建本地计划。本地存在尚未同步的修改时，本地版本优先。可在 `data\secrets.env` 使用 `FEISHU_TASK_ASSIGNEE_ID` 与 `FEISHU_TASK_ASSIGNEE_ID_TYPE` 指定负责人；未指定时，旧版保存的投递表链接仅用于读取文档所有者元数据，不访问工作表单元格。

投递记录表由用户自行维护。设置页不再提供投递表开关、连接检查或同步操作；旧版保存的启用状态会自动关闭。FeedNote 的模型路由、本地提交命令和飞书写入器均禁止新增或更新投递记录，现有表格内容不会被删除或修改。

FeedNote 仍维护三个独立飞书表格，职责严格分离：

- **FeedNote 计划表**：只接收本地 `plans` 中的真正待办及其状态更新；
- **用户投递记录表**：完全由用户维护；FeedNote 不读取或写入工作表单元格，也不会据此生成计划；
- **FeedNote 秘密表**：只接收本地保险箱中已解锁的秘密，单向写入，不从飞书回写本地；秘密值在表格中是明文；
- **FeedNote 备忘录表**：只接收用户明确点击“记”的原文、来源和记录时间，单向追加，不创建计划或待办；
- **自动路由**：普通职位详情进入记忆库；包含明确未来行动、约会或截止时间的内容进入计划；网页发布时间、职位发布日期不作为计划时间。

从旧版升级时，历史上由投递表反向生成的计划会依据旧映射从本地计划列表和 FeedNote 计划表中移除；投递记录表本身及原始投喂记录不会被删除或修改。

## 秘密备忘录

首次使用“藏”或打开“秘密备忘录”时，需要设置一个至少 6 个字符的独立主密码。主密码不写入磁盘；应用只保存 Argon2id 盐值和加密校验值，秘密正文及其元数据使用 AES-256-GCM 逐条加密。退出应用后必须重新解锁，忘记主密码无法恢复现有秘密。

“藏”不会创建普通投喂、记忆或计划。选中的秘密原文绝不发送给 LLM；只有在代码确认能定位并替换选区后，才发送以 `[SECRET]` 代替原文的有限周边文本。无法确认脱敏位置时，周边正文完全不发送。常规 JSON 导出不包含秘密。

“设置 -> 飞书秘密表”默认关闭。启用后，FeedNote 会创建独立的“FeedNote 秘密”表格，并在保险箱已解锁时进行本地到飞书的单向同步。**飞书表格中的秘密值是明文，不受本地主密码加密保护；其安全性取决于飞书账号、租户和文档权限。**该同步不回读或采用飞书侧的字段修改。

## 普通备忘录

普通备忘录用于没有确定时间的产品想法、创业计划和以后再考虑的事项。选中文字后点击“记”，FeedNote 只保存原文、来源和记录时间，不调用 LLM，也不创建桌面计划、飞书任务、投递记录或普通记忆。备忘卡片可编辑正文，来源和首次记录时间保持不变；编辑后沿用原本地 ID，并更新飞书中的同一行。使用已配置的飞书应用凭证自动创建“FeedNote 备忘录”表格；断网或同步失败不影响本地保存，后台会继续重试。

## 数据边界

- 原始投喂只追加，AI 无修改和删除权限；
- AI Gateway 只返回结构化判断，Memory Engine 校验后才可写数据库；
- 普通分类由 Memory Engine 校验后自动写入新版本；
- 同一主题的新进展可自动更新已有记忆，并继承全部原始来源；
- 删除任一来源会清除受影响的派生版本，再从剩余原文重建；
- 只有歧义与高风险冲突进入待澄清区；
- 永久删除只能由用户在界面中主动确认；
- 云调用只发送当前输入和最多 6 条、每条最多 800 字的候选记忆；
- 密钥不进入前端、数据库、日志和 JSON 导出；
- 不监听剪贴板、键盘，也不扫描目录。
- 选区监听阶段只读取 UI Automation 选区几何，不读取正文；点击圆点后只在内存暂存选中文字及前后各 1000 字，关闭弹窗立即丢弃且不联网、不落库；
- 选区功能不使用剪贴板、模拟复制或 OCR，不支持未暴露 Windows 无障碍文本接口的软件；
- 拖拽入口不读取剪贴板、聊天记录或来源文件，只接收用户主动拖到 FeedNote 图标上的最多 4000 字纯文本；图片和文件会被拒绝；
- 点击“记”明确授权选中文字写入本地普通备忘录和独立飞书备忘录表；不上传周边上下文，不调用 LLM，不进入计划、待办、投递表或秘密保险箱；
- 手机推送默认关闭；开启后只向用户配置的 HTTPS 地址发送计划卡片字段，不发送原始投喂、周边上下文、记忆库或本机路径；
- 飞书计划表同步默认关闭；开启后上传固定计划字段，并只回读已映射计划的完成状态；不从表格新建计划、不接受表格侧的正文、标题或时间修改；
- 飞书待办提醒默认关闭；开启后只同步计划字段和每条计划的提醒提前量（默认 3 小时，明确要求准时则为 0），并只按已有任务 GUID 回读标题、非全天开始时间和完成状态；不回读任务描述，不导入陌生任务，不读取通讯录或分配给其他用户；若未显式配置负责人，旧投递表链接只用于读取文档所有者元数据；
- 投递记录表由用户自行维护；FeedNote 不读取或写入任何工作表单元格，旧启用状态会自动关闭，旧链接只为兼容待办负责人解析而保留；
- 系统没有从投递表扫描、批量创建计划、新增记录或更新状态的运行路径；
- “藏”的原文只进入加密保险箱，不进入普通投喂、记忆、计划、全文索引、日志或常规 JSON 导出；
- 秘密原文不发送给 LLM；LLM 只处理已经由普通代码脱敏的有限周边文本，无法确认脱敏位置时不发送周边正文；
- 飞书秘密表默认关闭，只允许本地到飞书的单向同步；启用后秘密值在飞书端为明文，删除本地秘密只会清空其已映射远端行；
- 计划不会自动创建系统日历、发送邮件或操作其他账号；已授权的手机提醒和飞书同步之外，其他外部动作仍被禁止。
